Screen → endpoint map

Wire each screen to one primary call. Poll every 30–60s if you want live-feeling updates.

1. Map GET /api/hills

Markers from lat/lon. Colour from status.level.

2. Hill detail GET /api/hills/{id}

Shows sensors + NISAR + reasons.

3. Charts GET /api/hills/{id}/history

~7 days, 10-min samples (~1008 points).

4. Alerts GET /api/alerts

Use message_bn / message_en.

5. About (optional) GET /api/model-info

ROC-AUC + feature importance.

Status colours

Always take the colour from status.level — never invent your own thresholds in the UI.

SAFE

Green — low risk. Probability usually < 0.30.

WATCH

Amber — elevated. Model high but NISAR not confirmed, or mid probability.

DANGER

Red — show alert. Hold up to 24h via danger_until.

Endpoints & response shapes

All responses are JSON. Times are ISO-8601 UTC strings.

When does an alert appear?

Backend decides. Frontend only displays. DANGER needs all three:

1
Model probability ≥ 0.60
Shown as status.probability.
2
Ground sensor wet
latest_reading.soil_moisture ≥ 0.32
3
NISAR confirms
Wet satellite moisture or high creep → status.verified_by_nisar === true

If the model is high but NISAR does not confirm → WATCH (no panic alert). After DANGER, keep showing red until danger_until passes (up to 24 hours).
